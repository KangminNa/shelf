# Shelf 기능 명세

이 문서가 **기준선**이다. 코드는 여기에 맞춰 검증하고, 여기 없는 기능은 만들지 않는다.
각 항목은 `[F-n]` 번호로 참조한다. 상태는 ✅구현·⚠️부분·❌미구현.

## 0. 한 문장 정의

> Shelf는 개인 서버 한 대에서, Git 저장소나 Docker 이미지를 컨테이너로 배포하고
> 도메인·SSL·CI/CD를 대신 처리하는 셀프호스팅 앱 플랫폼이다.

앱의 계약은 하나다: **저장소 루트에 `Dockerfile`이 있고, 컨테이너가 포트 하나로 HTTP를 서빙한다.**

## 5. 인증·보안

| # | 기능 | 상태 |
|---|---|---|
| F-33 | 최초 접속 시 `/setup`에서 관리자 계정 1회 생성 (이후 차단) | ✅ |

| F-37 | 시크릿을 API 응답에서 제거하고 로그에서 마스킹 | ✅ |
| F-38 | git/이미지 입력값 셸 메타문자 검증 | ✅ |
| F-39 | 관리 UI·webhook 포트를 루프백 바인딩 (외부 노출은 80/443만) | ✅ |
| F-40 | 비밀번호 변경 UI | ❌ |
| F-41 | 시크릿 암호화 저장 (현재 `data/`에 평문) | ❌ |
| F-55 | 계정 복구: 서버 셸에서 비밀번호 교체·전체 초기화 (`npm run admin`) | ✅ |
| F-56 | 계정이 사라진 세션은 즉시 무효 (고아 세션 차단) | ✅ |

**비목표**: 이메일 기반 비밀번호 재설정. 메일 발송 의존성을 들이지 않는다 — 서버에 접근할 수 있는 사람만 복구할 수 있으면 충분하다.

## 8. 명시적 비범위

- 멀티 컨테이너 앱(compose 저장소), 멀티 유저·권한 분리, 오토스케일·클러스터
- HTTP 아닌 프로토콜 프록시, 앱의 DB/런타임 대행
- Dockerfile이 루트가 아닌 저장소, 포트 여러 개 노출하는 앱
